## 一句话总结

把 agentic RAG 中逐 token 生成 thought 和 subquery 的过程搬到连续隐空间，用单次前向传播产出 latent token 并直接用于检索，延迟降低约 90% 而性能基本持平。

## 解决什么问题

Agentic RAG 通过多步交互（生成 thought → 生成 subquery → 检索 → 再推理）提升复杂问答性能，但自回归逐 token 生成 thought 和 subquery 造成巨大延迟——实测 Search-R1 的总推理时间是 naive RAG 的 16-22 倍，其中 thought + subquery 生成占总延迟约 90%。本文的核心目标是在保持 agentic RAG 性能的前提下大幅压缩这两个阶段的延迟。

## 核心方法

### 1. Latent Token 生成（Sec 4.1）

用特殊 token 序列 $\tau^\ell_t = (\langle\text{think}_1\rangle, \dots, \langle\text{think}_m\rangle)$ 和 $s^\ell_t = (\langle\text{query}_1\rangle, \dots, \langle\text{query}_n\rangle)$ 替代显式自然语言 thought/subquery。这些特殊 token 在 prefill 阶段并行处理，取最后一层隐状态 $H^\tau_t$、$H^s_t$ 作为 latent thought/subquery token。默认 $m=4$（thought）、$n=16$（subquery）。

LLM 根据最后一个 latent thought token 解码一个 action token $\alpha_t \in \{\langle\text{query}\rangle, \langle\text{answer}\rangle\}$，决定继续检索还是输出最终答案。

### 2. Latent Retrieval（Sec 4.2）

- 轻量 projector $\text{Proj}_\text{ret}$（双向 self-attention + FFN）把 latent subquery token 映射到检索模型输入空间。
- 可训练检索模型产出 latent subquery embedding：$v_{s^\ell_t} = f_\text{ret}(\text{Proj}_\text{ret}(H^s_t); \theta_\text{ret})$。
- 冻结的参考检索模型对自然语言 subquery 编码得到参考 embedding $v'_{s_t}$。
- **KL 散度对齐目标**（替代 InfoNCE）：对每个候选文档 $d_i$ 计算基于 cosine similarity 的概率分布，最小化参考分布与 latent 分布之间的 KL 散度：

$$\mathcal{L}_\text{ret} = \frac{1}{|\mathcal{B}_s|} \sum_{s_t \in \mathcal{B}_s} \sum_{i=1}^{N_d} p_i(s_t) \log \frac{p_i(s_t)}{q_i(s_t)}$$

温度 $\beta = 0.03$，候选集由 top-16 伪相关文档 + batch 内负样本组成。

### 3. Latent Decoding（Sec 4.3）

- 两个 projector $\text{Proj}_\tau$、$\text{Proj}_s$ 分别将 latent thought/subquery token 投射回 LLM 输入空间，由 LLM 解码为自然语言。
- 推理时可选——不解码时延迟最低，解码时因各步解码条件独立可并行执行，仍比显式方法快。

### 4. 总损失

$$\mathcal{L} = \mathcal{L}_\text{gen} + \lambda_\text{ret} \mathcal{L}_\text{ret} + \mathcal{L}_\text{dec}$$

$\lambda_\text{ret} = 1$。$\mathcal{L}_\text{gen}$ 监督 action token 和最终答案，$\mathcal{L}_\text{dec} = \mathcal{L}^\tau_\text{dec} + \mathcal{L}^s_\text{dec}$。

### 训练设置

- LLM：Qwen2.5-7B-Base，LoRA rank=16，5 epochs，lr $1 \times 10^{-4}$，max 序列长 3000 tokens。
- 训练数据：NQ + HotpotQA 训练集，用 Search-R1 和 AutoRefine 生成的正确轨迹做 SFT。
- 硬件：2×H100 (94GB)，DeepSpeed ZeRO Stage 1，bfloat16 + FlashAttention-2。

## 关键实验结果

7 个 benchmark QA 数据集（NQ, TriviaQA, PopQA, HotpotQA, 2wiki, Musique, Bamboogle），Exact Match (EM) 指标，Wikipedia 2018 dump 作为检索语料（21M chunks）。

### 主要性能-延迟对比（Qwen3-Embedding-0.6B 检索模型）

| 方法 | 平均 EM (%) | 平均延迟 (ms) | 延迟降幅 |
|------|-----------|-------------|---------|
| Naive RAG | 25.67 | 359 | — |
| Search-R1 | 42.47 | 5,372 | — |
| AutoRefine | 42.73 | 4,827 | — |
| **LatentRAG♢** (Search-R1 轨迹) | **43.46 (+2.3%)** | **593** | **-89.0%** |
| **LatentRAG△** (AutoRefine 轨迹) | **43.79 (+2.5%)** | **512** | **-89.4%** |

- 跨 5 个检索模型（Qwen3-Embedding-0.6B, e5-base-v2, jina-v5-nano, harrier-270m, F2LLM-v2-330M），延迟降幅稳定在 85-92%，性能差异在 5% 以内。
- e5-base-v2 上性能下降较大（-3.6% ~ -4.0%），分析原因为其 embedding 空间严重各向异性。

### 带 Latent Decoding 的延迟

| 方法 | 平均延迟 (ms) | vs. baseline |
|------|-------------|-------------|
| LatentRAG♢ 不解码 | 593 | -89.0% |
| LatentRAG♢ 带解码 | 1,970 | -63.3% |
| LatentRAG△ 不解码 | 512 | -89.4% |
| LatentRAG△ 带解码 | 2,540 | -47.4% |

### Scaling 实验

- 检索模型 0.6B → 4B → 8B：LatentRAG♢ EM 从 43.46 → 44.71 → 45.76%，延迟几乎不增（512 → 531 → 554ms）。
- LLM 3B → 7B → 14B：LatentRAG♢ EM 从 35.59 → 43.46 → 45.11%，延迟从 447 → 512 → 772ms；Search-R1 延迟从 4106 → 5181 → 6041ms。

### 消融实验（平均 EM）

| 设置 | EM (%) | 检索成功率 (%) |
|------|--------|--------------|
| LatentRAG♢ (KL loss) | 43.46 | 61.27 |
| Cosine loss 替代 | 42.55 | 60.76 |
| InfoNCE loss 替代 | 41.86 | 58.60 |
| 去掉预训练检索模型 | 41.85 | 59.07 |
| 去掉 latent decoding loss | 40.61 | 60.64 |

## 局限与 Gap

1. **依赖 SFT 轨迹质量**：性能受限于 teacher 模型（Search-R1/AutoRefine）生成的轨迹质量，无法通过 RL 直接学习最优检索策略。作者明确指出未来可用强化学习改进。
2. **精确输出一致性不足**：failure case 表明 latent representation 有时产生拼写偏差（如 "Chilcott" vs "Chilcot"、"Montmoreiras" vs "Montmorency"），在 EM 评估下直接判错——latent 空间擅长抽象语义但对精确词汇输出较弱。
3. **Embedding 各向异性敏感**：e5-base-v2 等各向异性严重的检索模型上性能下降显著，说明方法对检索模型 embedding 空间的几何性质有要求。
4. **训练数据规模有限**：仅用 NQ + HotpotQA 训练集（~170K 样本），未探索更大规模训练数据的效果。
5. **未与 RL-based agentic RAG 做端到端对比**：当前 baseline 中的 RL 方法（R1-Searcher 等）用的是各自发布的权重，LatentRAG 本身只用了 SFT，尚未证明 latent 范式能否兼容 RL 训练。
