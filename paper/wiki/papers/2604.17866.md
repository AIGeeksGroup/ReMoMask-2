## 一句话总结

LAnR 用单个 LLM 在 latent space 内同时完成检索查询构造、文档匹配与答案生成，以 `[PRED]` token 的 hidden state 作为 dense retrieval vector，并通过轻量 MLP 控制头自适应决定何时停止检索，从而在五个 QA benchmark 上超越现有 RAG 方法，同时推理延迟降低 1.5--2.7 倍。

## 解决什么问题

1. **检索器-生成器架构割裂**：传统 RAG 系统用独立的 embedding 模型做检索、LLM 做生成，两者训练分离，无法共享表征能力。
2. **显式文本查询的开销**：现有 multi-hop RAG（如 Search-R1、IRCoT、AutoRefine）需在每一跳生成自然语言查询，产生大量中间 token，增加延迟。
3. **缺乏检索充分性的内在判断**：已有系统依赖 token 级别的显式推理（如 "I think I will answer now"）来决定是否继续检索，而非利用 LLM hidden state 中已有的不确定性信号。

## 核心方法

### Latent Query Construction（Section 2）

- 在输入 query 末尾追加特殊 token `[PRED]`，利用 causal self-attention 让其 hidden state 聚合全部上下文信息：$q = h_{[\text{PRED}]} \in \mathbb{R}^d$。
- 文档侧同样用同一 LLM 通过 last-token pooling 获得表征 $d_i = h^{\text{last}}_{D_i} \in \mathbb{R}^d$。
- 训练采用标准对比学习损失（InfoNCE），hard negative 按 ANCE 策略从模型自身检索错误中挖掘：
$$\mathcal{L}_{\text{CL}} = -\log \frac{\exp(\text{sim}(q, d^+)/\tau)}{\exp(\text{sim}(q, d^+)/\tau) + \sum_{j=1}^{N^-} \exp(\text{sim}(q, d_j^-)/\tau)}$$

### Multi-turn Framework（Section 3）

- 每轮 $r$，上下文 $c^{(r)} = (x, D^{(1)}, \dots, D^{(r-1)})$，追加 `[PRED]` 后抽取 $q^{(r)}$，用于检索 top-$K$ 文档。
- **Retrieval Control Head**：轻量 MLP（仅 $d+1$ 参数，对 3B 模型为 2049 个参数，占总参数 <0.0002%），对 $q^{(r)}$ 做 sigmoid 输出 $\hat{y}^{(r)} \in [0,1]$：
  - $\hat{y}^{(r)} \geq 0.5$：继续检索；$< 0.5$：停止，转入生成。
  - 训练标签由模型自身检索状态生成：当所有 gold 文档已被检索（$P \subseteq \mathcal{R}^{(r)}$）时 label=0，否则 label=1。
- **Adaptive Contrastive Target**：每轮只用"剩余未检索的 gold 文档" $P^{(r)} = P \setminus \mathcal{R}^{(r-1)}$ 作为正例，避免冗余检索。
- 总损失：$\mathcal{L} = \sum_{r=1}^R \mathcal{L}^{(r)}_{\text{CL}} + \lambda \mathcal{L}_{\text{NTP}} + \mu \mathcal{L}_{\text{ctrl}}$，其中 $\lambda=1, \mu=1$。对 retrieved token 和 `[PRED]` token 施加 loss masking。

### 动机实验（Appendix C）

- 在 Qwen-2.5 3B/7B 上验证：随着提供的 gold 文档数 $k$ 增加，首个 answer token 的预测熵 $H_k$ 单调下降（$E[H_k | P \subseteq G_k] < E[H_k | P \not\subseteq G_k]$），说明 hidden state 天然编码了"证据是否充分"的信号。

## 关键实验结果

### 主结果（Table 1，Qwen2.5-3B backbone，NQ+HotpotQA 联合训练）

| 方法 | NQ | TriviaQA | HotpotQA | 2Wiki | MuSiQue | Avg |
|---|---|---|---|---|---|---|
| AutoRefine-Instruct | 0.436 | 0.597 | 0.404 | 0.380 | 0.169 | 0.396 |
| AutoRefine-Base | 0.467 | 0.620 | 0.405 | 0.393 | 0.157 | 0.405 |
| **LAnR-Instruct** | **0.460** | **0.613** | **0.419** | **0.408** | **0.193** | **0.418** |
| **LAnR-Base** | 0.455 | 0.610 | 0.417 | 0.402 | 0.187 | 0.414 |

- LAnR-Instruct 平均 EM 0.418，超过 AutoRefine-Instruct 的 0.396（+0.022）。
- 在 MuSiQue（最难的 3-hop）上提升最显著：0.193 vs 0.169。

### 效率（Figure 2）

- LAnR 平均每 query 仅生成约 5 个 output token，而 Search-R1 约 163、AutoRefine 约 168（少约 30 倍）。
- 推理时间 0.81--1.61 s/query，对比 Search-R1 的 2.01--2.77 s、AutoRefine 的 2.15--2.34 s（快 1.5--2.7 倍）。
- 平均检索调用次数：LAnR 1.54--2.48 次 vs Search-R1 2.01--3.13 次。

### 检索质量 vs 专用 embedding 模型（Table 2）

- LAnR-Instruct 在 HotpotQA 上以约 5.5 篇文档达到 Recall 0.840，匹配 BGE R@5 的 0.832 和 E5 R@5 的 0.826。
- 在 2Wiki 上以约 5.1 篇达到 0.715，与 E5 R@10 的 0.717 持平。

### Ablation（Table 3）

- 去掉 control head（固定 5 篇检索预算）：multi-hop 大幅下降，Avg 从 0.418 降到 0.350（$\Delta=-0.068$）。
- 去掉 NTP loss masking：Avg 降 0.020。
- $\lambda_{\text{NTP}}=0$（无 NTP 损失）：性能崩溃至约 0.003。

### 扩展性（Table 7, Appendix E.2）

- 7B backbone 下 LAnR-7B-Base 在 HotpotQA 达 0.459 EM / 0.590 F1，2Wiki 达 0.415/0.612，MuSiQue 达 0.205/0.295，均为各方法最优。

### 统计显著性（Table 8）

- LAnR-Instruct vs AutoRefine-Instruct：paired T-test $p = 7.49 \times 10^{-3}$。
- LAnR-Instruct vs Search-R1-Instruct：$p = 1.31 \times 10^{-39}$。

### `[PRED]` token 数量（Appendix E.4）

- $N=1$ 收敛最快，在 multi-hop 上表现最好；$N=2,3$ 在 single-hop 上略有增益，但增加 multi-hop 优化难度。

## 局限与 Gap

1. **语料编码开销大**：用同一 LLM 编码整个检索语料（而非轻量 embedding 模型），每次换 backbone 都需重新编码，限制了频繁更新知识库的场景。
2. **Latent query 不可解释**：无法像文本查询那样审计检索原因，对高风险场景是隐患。
3. **评估局限**：仅在英文 open-domain QA + Wikipedia 语料上实验，未测试非英语、领域专用或长文档场景。
4. **backbone 局限**：仅测试了 Qwen2.5 3B/7B；未验证更大模型（如 14B/70B）或其他架构（如 LLaMA）的表现。
5. **训练依赖 gold 文档标注**：control head 需要 gold supporting document 集合 $P$ 来生成标签，单跳数据集通过 DPR 启发式弱监督构造，信号质量受限。
6. **固定 top-$K$ 和最大轮次**：默认 $K=3$、$R=4$，未探索动态 $K$ 或更灵活的终止策略。
