## 一句话总结

LG-Tok 把文本引导从生成阶段前移到 **motion tokenization 阶段**：用 Transformer（而非 CNN）做 tokenizer/detokenizer，在编码时将可学习 latent token 与 motion + 冻结 LLaMA 文本 embedding 拼接做 self-attention，量化后由 detokenizer 通过 cross-attention 解码；配合 language-drop scheme 实现推理时 language-free guidance，在 HumanML3D 和 Motion-X 上 FID 分别降至 0.057 和 0.088，大幅优于 MARDM 等 SOTA。

## 解决什么问题

VQ-based motion generation 的两阶段范式（tokenization → 生成模型）存在**重建与生成质量之间的根本矛盾**：

- 增加 token 数量可改善重建（rFID $0.143 \to 0.090$，token 数从 104 到 236），但 token 越多，生成模型学习越困难（gFID $0.230 \to 0.257$）。
- 现有 tokenizer 全部基于 **1D CNN**（4$\times$ 下采样），局部感受野无法支撑全局语言引导，也无法在 tokenization 阶段注入语义信息。
- 文本条件仅在生成阶段使用，tokenizer 产出的离散表示缺乏语义含义，给生成模型增加不必要的学习负担。

## 核心方法

### 1. Transformer-based Tokenizer/Detokenizer

抛弃 CNN 架构，用纯 attention 的 LLaMA 风格 Transformer：

- **Tokenizer**：预定义可学习 latent token $z_l \in \mathbb{R}^{T \times d}$，与线性映射后的 motion $m \in \mathbb{R}^{F \times d}$ 拼接做 self-attention（in-context），只保留 latent token 位置的输出：$z = E([z_l; m])$。
- **Detokenizer**：用可学习 mask token $\hat{m}_l \in \mathbb{R}^{F \times d}$ 通过 **cross-attention** 与反量化 embedding $\hat{z}$ 交互：$\hat{m} = D(\hat{m}_l, \hat{z})$。
- 架构细节：9 层 Transformer，4 头，latent dim 256，SwiGLU（dim=1024），RMSNorm，RoPE（base=100 适配短序列），UNet-like long skip connection。

### 2. Language-Guided Tokenization

冻结 LLaMA-3.2-1B 作为 text encoder，最大长度 77。文本 embedding 在 tokenizer 端与 motion、latent token 拼接做 in-context self-attention；在 detokenizer 端通过 cross-attention 引入。

三重收益：
1. latent token 在编码阶段同时学习运动表示和吸收语义知识；
2. 文本条件辅助 detokenizer 更好地重建输入运动；
3. 使离散表示更紧凑，降低生成模型学习难度（Motion-X 上 perplexity 从 146.5 降至 103.1，FID 从 0.257 降至 0.088）。

### 3. Language-Drop Scheme

训练时以 10% 概率移除文本条件（$t = \varnothing$），使 detokenizer 能支持 **language-free guidance decoding**：

$$\hat{m} = (1 + g) \times \hat{m}_c - g \times \hat{m}_u$$

其中 $\hat{m}_c$ 和 $\hat{m}_u$ 分别是有/无文本条件时 detokenizer 的输出，guidance scale $g$ 在 HumanML3D 为 2.0、Motion-X 为 1.0。

与以往方法在 logit 空间或噪声空间做 classifier-free guidance 不同，LG-Tok 的 guidance **在 motion space 执行、在 detokenization 阶段生效**。

### 4. Multi-scale Quantization (沿用 MoSa)

采用 MoSa 的 Scalable AutoRegressive (SAR) 框架：residual quantization 各层前插入下采样，构建多尺度 token $x^{(n)} \in [V]^{s_n}$，scale scheduler 如 LG-Tok-mid $S = (2, 4, \ldots, 36)$，共 10 个尺度。SAR 模型逐 scale 并行预测，推理步数从 49 减至 10。

## 关键实验结果

### HumanML3D（meng67 表示）

| 方法 | #Tokens | R-Precision Top-1 $\uparrow$ | FID $\downarrow$ | MM Dist $\downarrow$ | CLIP-score $\uparrow$ |
|---|---|---|---|---|---|
| MARDM (CVPR'25) | - | 0.500 | 0.114 | 3.270 | 0.642 |
| MoSa | 236 | 0.518 | 0.064 | 3.150 | 0.657 |
| **LG-Tok-mini** | **104** | **0.521** | **0.085** | **3.113** | **0.655** |
| **LG-Tok** | **236** | **0.542** | **0.057** | **2.997** | **0.669** |

### Motion-X

| 方法 | R-Precision Top-1 $\uparrow$ | FID $\downarrow$ |
|---|---|---|
| MARDM | 0.528 | 0.147 |
| MoSa | 0.513 | 0.210 |
| **LG-Tok-mini** (104 tokens) | **0.588** | **0.071** |
| **LG-Tok** (236 tokens) | **0.582** | **0.088** |

### Tokenizer 对比（重建 + 生成联合评估, Table 3）

- LG-Tok 替换 MoMask 的 tokenizer 后：重建 FID $0.029 \to 0.019$，MPJPE $31.5 \to 26.4$（HumanML3D）；生成 FID $0.247 \to 0.157$（Motion-X），验证 LG-Tok 对不同生成范式的通用性。
- 去除文本引导（w/o text guidance）后：生成 FID 从 0.057 回升至 0.062（HumanML3D）、0.088 升至 0.257（Motion-X），说明语言引导贡献显著，尤其在更大更多样的数据集上。

### Ablation 要点

- **Guidance 位置**：仅 tokenizer 端（FID 0.063）或仅 detokenizer 端（0.055）均不如双端注入（0.049）。
- **Text encoder**：LLaMA > CLIP > T5 > BERT（按重建 FID 排序）。
- **交互方式**：tokenizer 用 in-context（self-attention 拼接），detokenizer 用 cross-attention 为最优组合。
- **Language-drop scheme**：去掉后生成 FID 从 0.057 退化至 0.132（HumanML3D）、0.088 退化至 0.136（Motion-X），同时丧失 guidance 能力。
- **推理效率**：平均推理时间 0.121s（vs. MARDM 2.109s, MotionDiffuse 4.086s）。

### Limitations（作者自述）

- 全局 attention 覆盖 motion + text + latent token，显存约为 CNN tokenizer 的 10 倍（需 mixed-precision 才能在 24GB GPU 上训练）。
- 单卡 RTX 4090 tokenizer 训练约 2 天，远长于 CNN baseline 的数小时。

## 局限与 Gap

1. **检索缺失**：LG-Tok 完全是生成范式，不使用外部 motion 数据库检索；对于长尾或复杂组合语义，仅靠训练集内的语义对齐可能不够。
2. **语言引导依赖训练数据文本质量**：Motion-X 数据集文本描述更多样但也更噪声，语言引导的效果受限于文本-运动配对质量。
3. **固定 guidance scale**：$g$ 是全局超参数，不同文本/运动对可能需要自适应的 guidance 强度。
4. **与检索增强方法正交**：LG-Tok 的 Transformer tokenizer 和 language-guided latent 可以与 RAG 方法结合——论文未探索检索增强场景下 LG-Tok tokenizer 的表现。
5. **单一 text encoder**：仅用 LLaMA-3.2-1B，未探索更大的 LLM 或 motion-specific text encoder 是否有额外收益。

## 与 ReMoMask V2 的关联

### Plan A（latent 对齐检索）的直接启发

1. **Transformer tokenizer 产出 language-aligned latent**：LG-Tok 证明在 tokenization 阶段注入语言语义可产出更紧凑、更语义化的 latent 表示（t-SNE 可视化显示聚类更清晰），且降低下游生成模型学习难度。Plan A 的核心目标是将检索空间从 Part_TMR 迁移到 VQ-VAE latent space——LG-Tok 的 language-guided latent 天然比传统 VQ-VAE latent 更适合作为检索目标，因为它已包含文本语义信息，检索时 text query 与 latent motion 的对齐不再需要额外的跨模态桥接。
2. **可借鉴的 tokenizer 架构**：LG-Tok 的 Transformer tokenizer + in-context language injection 可直接替换 ReMoMask V1 的 RVQ-VAE encoder，使检索和生成共享同一个 language-aligned latent space。
3. **Language-drop scheme 可复用**：Plan A 中 detokenizer 需要同时接受检索 motion 和文本条件；LG-Tok 的 language-drop 方案可扩展为 "retrieval-drop"，训练时随机丢弃检索结果，使模型在推理时可做 retrieval-free guidance（类似 classifier-free guidance 的检索版本）。
4. **Multi-scale quantization 的优势**：MoSa/LG-Tok 的多尺度 token（粗到细）与 Plan A 的多粒度检索思路天然吻合——粗尺度 token 可用于快速检索候选，细尺度 token 用于精确匹配。

### Plan B（迭代动态检索）的参考

- LG-Tok 的 SAR 生成过程（逐 scale 预测）本身就是迭代细化，每一步生成的中间 token 可作为下一轮检索的 query。Plan B 可在 SAR 的 scale-by-scale 框架上嵌入检索步骤：先用粗尺度生成结果检索运动片段，再用检索结果 condition 细尺度生成。

### 具体可借鉴的技术点

- LLaMA-3.2-1B 作为冻结 text encoder（优于 CLIP/T5/BERT）
- Tokenizer 端用 in-context、detokenizer 端用 cross-attention 的交互设计
- RoPE base=100 适配短序列任务
- 10% language-drop 概率 + guidance scale 2.0/1.0 的经验值
- OOD 数据（$\geq$200 帧长序列）训练增强 tokenizer 鲁棒性
