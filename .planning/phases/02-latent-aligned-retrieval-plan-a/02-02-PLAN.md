   - 改为加载 RVQVAE: 用 utils/get_opt.get_opt(vq_opt_path) 读取 VQ 配置，构建 RVQVAE(vq_opt, 263, ...)，加载 checkpoint
   - 冻结 RVQVAE: vq_model.eval()

3. Motion 编码替换（核心改动）:
   - 原代码: model.encode_motion(motions)['global'] 返回 Part_TMR 512d 向量
   - 新代码: 
     a. 拼装 2D motion 输入: 参考 RVQVAE.forward() 中 x2d 的处理，需要从 whole2parts 的 6 个部件拼出 (B, T, J0, JD0) 格式的 joints tensor
     b. 但更直接的方法: 直接加载原始 motion (B, T, 263) 和 joints (B, T, 22, 12)，调用 RVQVAE 的 encoder2d
     c. 具体步骤:
        - x2d = joints tensor, shape (1, T, 22, 12)
        - pad joints: torch.nn.functional.pad(x2d, (0,0,1,1)) if J0==22 -> (1, T, 24, 12)
        - z_e = vq_model.encoder2d(rearrange(x2d, 'b t j d -> b d t j'))  -> (1, code_dim2d, T/4, 6)
        - z_e_pooled = z_e.mean(dim=[2, 3])  -> (1, code_dim2d)
        - z_e_pooled = F.normalize(z_e_pooled, dim=1)  -> (1, code_dim2d)
     d. 注意: 需要从原始 motion 中构建 joints tensor。参照 data/t2m_dataset.py 的数据加载逻辑来构建 joints。

   实际实现（更简洁的路径）: 直接用 RVQVAE.encode() 方法的中间结果。但 encode() 直接调用 quantizer 返回 code_idx，不暴露 z_e。所以需要直接调用 encoder2d:
   
   - 加载原始 motion (B, T, 263)
   - 调用 data/t2m_dataset.py 中的 joints 提取逻辑（或参考 RVQVAE.forward() 中 x2d 的输入构造）
   - 具体: 需要理解 joints 从 motion (263维) 怎么提取成 (T, 22, 12)

   参考 RVQVAE.forward() 的输入: x1d 是 (B, T, 263) 原始 motion，x2d 是 (B, T, J0, JD0) joints 表示。在 t2m_dataset.py 中，joints 是单独计算的。

   最简实现方案: 不从 build_rag_database.py 的 whole2parts 走，而是直接参考 train_mask_transformer_ddp.py 中数据集的 joints 字段。使用 Text2MotionDataset 直接加载数据，它已经提供了 (motion, joints, m_lens) 格式。

   最终方案:
   - 导入 Text2MotionDataset，用 train split 构造 dataset
   - 遍历 dataset，每个样本取 motion 和 joints
   - 用 RVQVAE 的 encoder2d 提取 z_e
   - 保存到 database_ze/

4. 文本编码: 暂时保留 Part_TMR 的 text encoding（因为 query_projector 还没训好）。或者用 CLIP 的原始 512d text embedding。暂时存一份 CLIP 512d text embedding 到 database_ze/encoded_texts_clip.npy，后续 LA-03 训完 projector 后再替换。

5. 输出格式（per D-10, D-12）:
   - database_ze/encoded_motions.npy — shape (N, 1, code_dim2d)，与原格式 (N, 1, 512) 形式一致，只是 D 变化
   - database_ze/encoded_texts_clip.npy — shape (N, 1, 512)，CLIP 原始 text embedding

   - database_ze/tag_lists.npy — 与原格式一致
   - database_ze/motion_tokens.npy — 与原格式一致（直接复制 token 保存逻辑）
   - database_ze/metadata.json — 记录 code_dim2d、encoder_type="rvqvae_2d"、timestamp、样本数

6. 命令行参数: --vq_name (VQ checkpoint 名)、--output_dir (默认 database_ze)、--device

重要: 从 data/t2m_dataset.py 了解 joints 的构造方式。如果 dataset 不直接提供 joints，需要参考 RVQVAE.forward() 中 x2d 的输入是怎么构造的——在 train_mask_transformer_ddp.py 中，batch 解包为 (captions, motion, joints, m_lens)，说明 dataset 确实提供 joints。

1. 类名: ZeRetriever(nn.Module)，继承自 Retriever ABC

2. __init__(self, database_path, query_projector_path, top_k, num_retrieval, use_shuffle):
   - 加载 database_ze/ 中的 npy 文件:
     - motion_features: np.load(encoded_motions.npy)[:, 0, :] -> (N, code_dim2d)
     - text_features: 暂时用 encoded_texts_clip.npy（LA-03 训完后替换为 projector 输出）
     - motion_names, captions
   - register_buffer 注册 motion_features 和 text_features
   - 加载 query_projector (如果 path 不为 None):
     - self.query_projector = 加载训好的 MLP
   - 加载 CLIP model 用于 encode query text（如果没有 projector，用 CLIP 直接查文本库）

3. forward(self, captions) -> re_dict:
   与 MocoTmrRetriever.forward() 接口完全一致:
   - 对每个 caption: encode text -> 用 query_projector 映射到 z_e 空间 -> cosine similarity with motion_features -> top-k
   - 返回 re_dict = {"re_text": (B, K, 1, D), "re_motion": (B, K, 1, D)}
   - 这里 D = code_dim2d（z_e 维度），不再是 512

   关键区别: re_dict 中的 D 可能不等于 512。后续 LA-04 会在 SSTA 中处理维度适配。

4. get_knn_samples(self, caption, k) 方法:
   - 与 MocoTmrRetriever 相同的去重逻辑（同一 motion 的不同 caption 不重复选取）
   - 与 MocoTmrRetriever 相同的 shuffle 逻辑

5. 接口约定:
   - forward() 返回的 re_dict 键名和维度结构与 MocoTmrRetriever 一致
   - 唯一变化: 最后一维 D 可能从 512 变为 code_dim2d
   - 调用者需处理维度差异（LA-04 负责）

注意: 在 query_projector 训好之前，ZeRetriever 的文本查询走 CLIP text -> cosine sim with motion_features（跨空间查询，效果不好但能跑通流程）。LA-03 训完后，改为 CLIP text -> projector -> cosine sim with motion_features。
