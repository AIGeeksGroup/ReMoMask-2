Lesson 02 — 双分支 RVQ-VAE：运动 token 化的核心引擎

从 263 维连续运动到离散 token 序列 — 1D 全局分支与 2D 关节分支的协同设计

1. HumanML3D 263 维运动表示的拆解

ReMoMask 的输入是 HumanML3D 格式的标准化运动序列，每帧 263 维。 数据集在加载时按如下方式对 std 做了分段 bias 缩放，显式标出了各段的语义边界：

设计决策：根关节与非根关节的不对称性

位置和旋转只覆盖 21 个非根关节（索引 1-21），不含根关节（索引 0）。 根关节的全局位移用 4 维参数化（旋转速度 + 平面速度 + 高度），避免了绝对坐标带来的 分布偏移问题。而速度场覆盖全部 22 个关节（含根关节），脚部接触则只有 4 维二值信号。 这种不对称直接影响了后续 2D 分支中 x_joints 的构建方式。

2. 1D 分支：Conv1d 全局编码器

1D 分支接收完整的 263 维运动序列，用纯时序卷积编码全局运动模式。

注意：Encoder 与 Decoder 的 reverse_dilation 传参不对称

Encoder 在构造 Resnet1D 时不显式传 reverse_dilation 参数，依赖构造器默认值 True； 而 Decoder 显式传了 reverse_dilation=True。 两者行为一致（都是 [9,3,1] 顺序），但耦合方式不同 — 如果未来修改了 Resnet1D 的默认值，只有 Encoder 会受影响。

2.2 ResConv1DBlock 细节

models/vq/resnet.py:12-69 已验证

ResConv1DBlock(n_in=512, dilation=d)  已验证

  x_orig = x
  x = Norm(x)                    ── 默认 nn.Identity()（norm=None）
  x = Activation(x)              ── 默认 ReLU
  x = Conv1d(512, 512, k=3, s=1, p=d, dilation=d)    扩张卷积
  x = Norm(x)
  x = Activation(x)
  x = Conv1d(512, 512, k=1, s=1, p=0)                1x1 逐点卷积
  x = Dropout(0.2)(x)
  x = x + x_orig                                      残差连接

设计决策：指数扩张卷积 + 逆序

Resnet1D 在 depth=3 层中使用指数增长的 dilation： dilation_growth_rate^i = [1, 3, 9]。 因为 reverse_dilation 默认为 True （resnet.py:73 的构造器默认参数）， 实际执行顺序是 [9, 3, 1] — 先用大 dilation 捕捉长程依赖， 再用小 dilation 精修局部细节。 已验证

dilation=9 的 3×1 卷积有效感受野为 19 帧（1 + 2×9 = 19，约 1 秒 @20fps）， 在 49 个 token 的序列上已能覆盖 ~40% 的时间跨度。 已验证

3. 2D 分支的核心创新：关节级 token 化

2D 分支是 ReMoMask 相对于 T2M-GPT / MMM 等前作的关键创新。 它将运动视为 (时间 × 关节) 的 2D 网格， 用 Conv2d 在时间和关节两个维度同时下采样， 让每个 token 同时编码一段时间和一组关节的运动模式。

3.1 22 关节 → pad 到 24 → 下采样到 6 组

models/vq/model.py:88-89,110-111 已验证

2D 分支输入处理

  x2d 原始形状: [B, T, 22, 12]      ── 来自数据集的 x_joints

  Pad(0,0,1,1):                      在关节维度两侧各补 1 个零关节
  [B, T, 24, 12]

  rearrange('b t j d -> b d t j'):   转为 Conv2d 格式
  [B, 12, T, 24]                     12 通道 = 每关节特征维度
                                     T × 24 = 时空 2D 网格

  已验证

设计决策：为什么 pad 到 24？

22 不是 4 的倍数（2 次 stride=2 下采样需要被 4 整除）， 所以在关节维度补齐到 24 = 6 × 4。对 KIT 数据集（21 关节）则 pad(0,0,1,2)（补到 24）。补零不引入假信号， 仅保证卷积的空间对齐。 已验证

3.3 六个关节组的感受野映射

2 次 stride=2 的 Conv2d 在关节维度将 24 个位置压缩为 6 个。 每个输出位置的直接感受野约覆盖 7-8 个相邻关节索引 （计入 ResNet2D 的扩张卷积后实际感受野更大）。 按 HumanML3D 的关节索引排列，6 个组大致对应： 

关节组感受野映射（含 padding，近似覆盖范围）

  组 0:  pad, j0(pelvis), j1(L-hip), j2(R-hip), j3(spine)
         → 躯干中心 + 髋部

  组 1:  j2(R-hip) ~ j7(chest), j4(L-knee), j5(R-knee)
         → 双腿上段 + 脊柱

  组 2:  j5(R-knee) ~ j11(R-foot), j8(R-ankle), j9(neck)
         → 双腿下段 + 颈部

  组 3:  j9(neck) ~ j14(R-collar), j12(head), j13(L-collar)
         → 头颈 + 肩部

  组 4:  j13(L-collar) ~ j19(R-wrist), j16(L-elbow), j17(R-elbow)
         → 双臂

  组 5:  j17(R-elbow) ~ j21(R-hand), j20(L-hand), pad
         → 前臂 + 手部

  注: 这不是精确的分区划分，Conv2d 的感受野有大量重叠，
  且 Resnet2D 的扩张卷积 (dilation 9) 能跨越几乎所有组。
  分组是网络自动学到的，不是硬编码。

设计决策：Conv2d 而非手动关节分组

与 T2M-GPT 等将所有关节特征拍平为 1D 序列不同， 2D 分支保留了关节的空间维度。Conv2d 的归纳偏置天然鼓励 相邻关节共享特征，而 Resnet2D 的扩张卷积让远距关节也能交互。 这比手动定义关节组更灵活 — 网络可以学到超越解剖学先验的分组。

不过，由于 HumanML3D 的关节索引是左右交错排列的 （L-hip=1, R-hip=2, L-knee=4, R-knee=5）， Conv2d 的局部感受野会自然地在同一组内混合左右肢体， 这对双侧协调运动（走路、跑步）是有利的。

3.4 每个关节组独立 RVQ 量化

models/vq/model.py:118 已验证

x2d_quantized, code_idx2d, commit_loss2d, perplexity2d = self.quantizer2d(
    rearrange(x2d_encode, 'b d t j -> (b j) d t'),      # [B*6, 512, T/4]
    sample_codebook_temp=0.5
)

关键操作是 rearrange('b d t j -> (b j) d t')： 将 6 个关节组沿 batch 维度展开。对于 quantizer2d 来说， 它看到的是 [B×6, 512, T/4] 的 1D 序列 — 每个关节组被当作独立样本进行 RVQ 量化。 已验证

设计决策：共享码本 vs 独立码本

6 个关节组共享同一个 quantizer2d（同一套码本）， 而非每组各有一个量化器。共享码本是一种正则化手段： 不同身体部位被迫使用同一套运动"词汇"，这鼓励码本学到更通用的运动原语 （比如"摆动"、"弯曲"这种跨部位通用的模式）。 同时也大幅减少参数量：3 层 RVQ × 512 码字已足够， 不需要 6 × 3 × 512 个码字。 已验证

量化后的码本索引重组过程： 

# quantizer 输出: code_idx2d 形状 [B*6, T/4, num_quantizers]
# 在 encode() 中重组:
code_idx2d = code_idx2d.reshape(B, self.J, T, n_qt).permute(0, 2, 1, 3)
# → [B, T/4, 6, num_quantizers]

models/vq/model.py:94-96 — 最终每个时间步、每个关节组有 num_quantizers（默认 3）个码本索引。 已验证

补充：encode() 与 forward() 的量化温度差异

forward() 训练时调用 quantizer 传入 sample_codebook_temp=0.5 （Gumbel 采样，见第 4.3 节），而 encode() 调用 quantizer.quantize() 时 temperature 默认为 0 — 退化为纯最近邻选择，不使用 Gumbel 采样。 这是一个关键的训练/推理行为差异：训练时用随机性促进码本探索， 推理编码时用确定性保证可复现。

4. Residual VQ：多层码本的实现细节

models/vq/residual_vq.py:28-169

RVQ 遵循 SoundStream (Zeghidour et al., 2021) 的 Algorithm 1： 多层量化器逐层编码残差，每层只需捕捉上一层未能表达的信息。

4.1 前向传播流程

ResidualVQ forward（num_quantizers=3 为例）  已验证

  输入: x                    [B, 512, T]   ── encoder 输出
  residual = x
  quantized_out = 0

  ┌─ Layer 0 ──────────────────────────────────────────────
  │  q_0, idx_0, loss_0 = QuantizeEMAReset(residual)
  │  residual = residual - q_0.detach()        只截断梯度, 不影响 residual 值
  │  quantized_out += q_0
  └────────────────────────────────────────────────────────

  ┌─ Layer 1 ──────────────────────────────────────────────
  │  q_1, idx_1, loss_1 = QuantizeEMAReset(residual)       编码 Layer 0 的残差
  │  residual = residual - q_1.detach()
  │  quantized_out += q_1
  └────────────────────────────────────────────────────────

  ┌─ Layer 2 ──────────────────────────────────────────────
  │  q_2, idx_2, loss_2 = QuantizeEMAReset(residual)       编码 Layer 0+1 的残差
  │  residual = residual - q_2.detach()
  │  quantized_out += q_2
  └────────────────────────────────────────────────────────

  输出:
    quantized_out = q_0 + q_1 + q_2              累加量化结果
    all_indices = stack([idx_0, idx_1, idx_2])    [B, T, 3]
    all_losses = mean(loss_0, loss_1, loss_2)     commitment loss 取平均
    all_perplexity = mean(perp_0, perp_1, perp_2)

残差计算的 .detach() 在 residual_vq.py:146： 梯度不通过残差路径反传到前面的量化器，每层量化器独立优化。 已验证

4.2 Quantize Dropout

models/vq/residual_vq.py:112-127 已验证

设计决策：随机丢弃后面的量化层

训练时以概率 quantize_dropout_prob（默认 0.2，来自 argparse）触发 dropout。 触发后，从 [cutoff_index, num_quantizers) 中均匀采样一个截断点 start_drop_quantize_index，索引大于截断点的所有层跳过 （截断点所在的层本身仍正常执行），码本索引填 -1。 已验证

这迫使前面的层尽量独立地编码足够的信息，不依赖后续层的残差补偿。 好处是推理时可以用更少的码本层（牺牲少量质量换取更短的 token 序列）， 也让第一层码本的语义更集中、更适合 mask transformer 建模。 

# residual_vq.py:112-117
should_quantize_dropout = self.training and random.random() < self.quantize_dropout_prob

if should_quantize_dropout:
    start_drop_quantize_index = randrange(self.quantize_dropout_cutoff_index, num_quant)
    null_indices = torch.full(null_indices_shape, -1., device=device, dtype=torch.long)

补充：Quantize Dropout 的边界行为

默认 num_quantizers=3、cutoff_index=0 时， randrange(0, 3) 可以返回 0、1 或 2。由于跳过条件是 quantizer_index > start_drop_quantize_index（严格大于）， 当 start_drop_quantize_index=2 时，所有三层（0、1、2）都不满足 > 2，实际不丢弃任何层。 因此"20% 概率触发 dropout"并不等于"20% 的训练步真的少跑层" — 有约 1/3 的触发情况实际上等于不丢弃。

补充：force_dropout_index 参数

ResidualVQ.forward() 还接受一个 force_dropout_index 参数（residual_vq.py:122-126），可以在推理时强制截断 RVQ 层数。 传入后会覆盖随机采样的截断点，让指定索引之后的层全部跳过。 这在测试不同码本层数对重建质量的影响时很有用。

补充：构造器默认值与 argparse 默认值的差异

ResidualVQ.__init__ 的 quantize_dropout_prob 构造器默认值是 0.5（residual_vq.py:34）， 但 argparse 默认值是 0.2（vq_option.py）。 类似地，RVQVAE.__init__ 的 down_t 构造器默认值是 3（models/vq/model.py:14）， 但 argparse 默认值是 2。 实际训练始终通过命令行参数传入，因此用的是 argparse 的值。 读代码时注意区分这两层默认值，避免混淆。

4.3 单层量化器：QuantizeEMAReset

models/vq/quantizer.py:35-158 已验证

码字选择：Gumbel 采样

quantizer.py:67-80 已验证

def quantize(self, x, sample_codebook_temp=0.):
    distance = ||x||^2 - 2 * x @ codebook^T + ||codebook||^2    # [N*T, nb_code]
    code_idx = gumbel_sample(-distance, temperature=sample_codebook_temp,
                             stochastic=True, training=self.training)

训练时（sample_codebook_temp=0.5，见 models/vq/model.py:105）， 在负距离上叠加 Gumbel 噪声再取 argmax，等价于按 softmax 概率采样。 这比硬 nearest neighbor 更利于码本探索，减少 codebook collapse。 推理时 temperature=0，退化为标准最近邻。 已验证

EMA 码本更新 + 死码重置

quantizer.py:100-117 已验证

EMA 更新（mu=0.99）  已验证

  每次前向传播后:
  1. 统计每个码字被选中的次数 code_count 和对应 encoder 输出的加权和 code_sum
  2. EMA 更新:
       code_sum  ← 0.99 * code_sum  + 0.01 * batch_code_sum
       code_count ← 0.99 * code_count + 0.01 * batch_code_count
  3. 更新码本:
       codebook = code_sum / code_count    （对活跃码字）
  4. 死码重置:
       if code_count < 1.0:
           codebook[dead] = random_training_sample + noise

设计决策：Reset 而非 Restart

QuantizeEMAReset 检测使用率低于 1.0 的码字， 将其替换为当前 batch 中随机挑选的 encoder 输出（_tile 方法， quantizer.py:49-58）加微小噪声。这和 QuantizeEMA （quantizer.py:160-180）的区别在于后者不做重置， 死码会永久保留旧值。Reset 策略对抗 codebook collapse 更激进。 已验证

Commitment Loss 与 Straight-Through Estimator

quantizer.py:147-150 已验证

# Commitment loss: 让 encoder 输出靠近码字
commit_loss = F.mse_loss(x, x_d.detach())

# Straight-through estimator: 前向用量化结果，反向传梯度给 encoder
x_d = x + (x_d - x).detach()

x_d - x 被 detach 后加回 x， 前向值等于 x_d（量化后码字），但梯度直接穿过到 x。 这是 VQ-VAE 的标准 trick，让不可微的 argmin 操作可以训练。 已验证

Perplexity 计算

quantizer.py:89-98 已验证

prob = code_count / sum(code_count)
perplexity = exp(-sum(prob * log(prob)))

Perplexity 衡量码本利用率：若 512 个码字被均匀使用， perplexity 接近 512；若只有少数码字活跃，perplexity 远低于 512。 训练中监控 perplexity 是诊断 codebook collapse 的关键指标。 已验证

5. 融合机制：两个分支的合体

models/vq/model.py:119-138

5.1 2D 分支量化后的 linear_merge

6 个关节组独立量化后，需要一个交叉关节组的信息交换步骤： 

linear_merge 数据流  已验证

  quantizer2d 输出:     [B*6, 512, T/4]
  reshape:              [B, 6*512, T/4]  = [B, 3072, T/4]
  permute + reshape:    [B*T/4, 3072]
  linear_merge:         nn.Linear(3072, 3072)     ── 跨组全连接
  reshape + permute:    [B, 3072, T/4]
  reshape:              [B, 6, 512, T/4]
  rearrange:            [B, 512, T/4, 6]  = 'b d t j'

models/vq/model.py:55 — self.linear_merge = nn.Linear(code_dim2d * J, code_dim2d * J) 已验证

设计决策：为什么在量化之后加 linear_merge？

量化操作是逐组独立的，丢失了组间关联。linear_merge 在量化后、解码前插入一个全连接层，让 6 个组的量化结果相互交流。 这弥补了独立量化带来的信息割裂，让 decoder 看到的输入已经融合了全身信息。 相当于一个轻量级的"全身一致性"约束。

5.3 最终线性融合 linear_out

models/vq/model.py:58, 138 已验证

self.linear_out = nn.Linear(input_width * 2, input_width)  # Linear(526, 263)

# 前向传播:
x_out2d = self.linear_out(torch.concat([x_out1d, jmotion], dim=2))
# x_out1d: [B, T, 263]   ── 1D 分支解码输出
# jmotion:  [B, T, 263]   ── 2D 分支重组后的运动
# concat:  [B, T, 526]
# output:  [B, T, 263]

设计决策：线性融合而非更复杂的 attention

融合层只是一个线性投影，没有用 cross-attention 或 gating mechanism。 这是一个刻意的简洁选择 — 两个分支已经各自提供了完整的 263 维重建， linear_out 只需学习在每个特征维度上如何加权混合两个来源。 已验证

从训练损失来看（models/vq/vq_trainer.py:70）， 三路输出都有独立的重建监督：

  • loss1: 1D 分支单独重建 → 训练 x_out1d
  • loss2: 2D 分支单独重建 → 训练 jmotion
  • loss: 融合后重建 → 训练 linear_out 的混合权重

总损失 loss_all = (loss1 + loss2) + loss （models/vq/vq_trainer.py:145），三项等权相加。 已验证

6. jmotion 组装过程：从关节张量回到 263 维

models/vq/model.py:123-136

x2d_out 的形状是 [B×T, 22, 12] （去 padding 之后）。将其重组回 263 维的 jmotion 需要对根关节和非根关节分别处理： 

jmotion 组装映射（HumanML3D, J0=22）  已验证

  jmotion = zeros([B, T, 263])

  ┌─ 根关节 j=0 的特殊处理 ──────────────────────────────────────────
  │
  │  jmotion[:,:, 0:4]   = x2d_out[:, 0, 0:4]     根特征 (rot_vel, lin_vel, root_y)
  │  jmotion[:,:, 259:263] = x2d_out[:, 0, 4:8]    脚部接触 (4 维)
  │
  │  注: 输入 x_joints 中根关节的 [0:8] 是全零的!
  │  因此 2D 分支在这些位置的重建趋近于零,
  │  实际根特征和脚部接触由 1D 分支通过 linear_out 融合提供。
  │
  └────────────────────────────────────────────────────────────────────

  ┌─ 非根关节 j=1..21 ───────────────────────────────────────────────
  │
  │  jmotion[:,:, 4:67]   = x2d_out[:, 1:, 0:3]    位置 ric_data  (21×3=63)
  │  jmotion[:,:, 67:193] = x2d_out[:, 1:, 3:9]    旋转 rot_data  (21×6=126)
  │
  └────────────────────────────────────────────────────────────────────

  ┌─ 全部关节 j=0..21 ──────────────────────────────────────────────
  │
  │  jmotion[:,:, 193:259] = x2d_out[:, :, 9:12]   速度 velocity  (22×3=66)
  │
  │  根关节的速度是 x_joints 中唯一非零的输入信号(j=0, [9:12])，
  │  经过编码-量化-解码后在这里被还原。
  │
  └────────────────────────────────────────────────────────────────────

组装逻辑在 forward() 和 forward_decoder() 中完全一致 （models/vq/model.py:131-135 vs 165-169），保证训练和推理行为对齐。 已验证

设计决策：根关节的"空壳"编码

2D 分支输入中，根关节的 12 维特征只有速度（[9:12]）是有信号的， 其余 9 维全零。但 jmotion 组装时仍然从根关节的解码输出中取 [0:4] 作为根特征、 [4:8] 作为脚部接触。 已验证

实际效果：根特征和脚部接触完全依赖 1D 分支，2D 分支的 jmotion 在这些位置贡献接近零，linear_out 学到的混合策略 会自然将这些维度的权重分配给 1D 分支输出。

补充：loss2 中 loss_explicit_ts 的 ground truth 来源

loss2 的关节位置额外监督项 loss_explicit_ts 中， pred_local_pos_ts 是从 2D 分支 jmotion 中取的位置维度 （jmotion[..., 4:67]），但 ground truth local_pos 取自原始 263 维 motion 的相同索引区间， 而非从 x_joints 重组的 jmotion。 这意味着 2D 分支的位置重建是和原始运动数据对齐的， 即使 jmotion 的组装方式与原始 263 维略有结构差异 （根关节位置全零），位置监督仍然直接对标原始数据。

9. LengthEstimator：从 CLIP embedding 预测 token 长度

models/vq/model.py:175-209 已验证

在推理时，模型需要知道给定文本应该生成多长的运动。 LengthEstimator 将长度预测建模为分类问题： 

LengthEstimator 结构  已验证

  输入: text_emb           [B, 512]    ← CLIP text embedding

  Linear(512, 512) + LayerNorm + LeakyReLU(0.2)
  Dropout(0.2)
  Linear(512, 256) + LayerNorm + LeakyReLU(0.2)
  Dropout(0.2)
  Linear(256, 128) + LayerNorm + LeakyReLU(0.2)

设计决策：分类而非回归

output_size 等于可能的 token 长度数量。 HumanML3D 的运动长度是 unit_length（默认 4）的整数倍， 所以长度被离散化为 m_lens // unit_length 个类别。 用 CrossEntropyLoss 训练（models/vq/vq_trainer.py:225）， argmax 取最可能的长度。 已验证

分类比回归更适合这个任务：运动长度的分布是多峰的 （"走路"可能 2-3 秒，"坐下"可能 1-2 秒），回归会被均值拉向中间， 而分类可以精确命中峰值。

权重初始化用高斯分布（models/vq/model.py:199-206）， 标准差 0.02，LayerNorm 的 weight 初始化为 1.0、bias 初始化为 0.0。 已验证
